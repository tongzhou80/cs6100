CISC 6100

Software Engineering

Instructor: Tong Zhou • Time & Location: TBA

A project-driven introduction to modern software engineering. Students will iteratively design and build an online Gomoku game while learning requirements analysis, modeling (UML/OOP), design patterns, testing, web programming, and tooling (Git & CI/CD). The course emphasizes Agile thinking, MVPs, and continuous improvement.

Prereqs
Basic programming skills, basic data structures.
Format
Lectures + team projects + midterm.
Outcomes
Ship an MVP, write tests, and present a working system.

Reference Textbook

Ian Sommerville, Software Engineering, 10th edition. Additional readings will be posted as needed.

Syllabus (Overview)

Course Objectives

  • Practice iterative, Agile-informed development via a real web app.
  • Translate requirements into design, implementation, and tests.
  • Apply OOP, MVC, and basic design patterns.
  • Use Git and CI/CD to ship a working MVP.

Assessment

  • Team Project: 50%
  • Individual Assignments: 20%
  • Midterm Exam: 20%
  • Participation: 10%

Key Dates

  • Milestone A (Local play): Week 5

  • Final Presentations: Week 14

Policies

Collaboration

Discuss concepts freely. All submitted code and writing must reflect your team’s or your own understanding. Cite any external resources used.

Late Work

Each team has 3 total late days for the semester on milestones/assignments (max 2 days per item). After that, 10% penalty per day. Presentations cannot be late.

AI Use Policy

Goal: Use AI to learn and improve productivity, not to outsource understanding.

  • Allowed (with citation): Using tools like ChatGPT/Gemini to clarify APIs, syntax, or get high‑level ideas; using completion tools (Copilot, Cursor, Codeium, Windsurf) for small code suggestions.
  • Not allowed: Submitting AI‑generated solutions you do not understand; generating substantial portions of assignments/exams; using AI during closed‑book assessments.
  • Transparency: Document AI assistance in READMEs or code comments (e.g., “Used Cursor suggestion for WebSocket reconnect loop, then modified to pass tests”).
  • Accountability: You must be able to explain any submitted code. During demos or code reviews, expect spot questions.

Grading Breakdown

Team Project (50%)

  • Functionality (20 pts): MVP (board, turns, win) + extended features (menus, invite link, chat).
  • Code Quality & Testing (10 pts): Modularity/MVC, readability, README, unit & integration tests.
  • Design Process & Iterations (10 pts): Requirements, UML, commit history, trade‑off rationale.
  • Presentation & Collaboration (10 pts): Final demo, slides, Q&A, peer evaluations.

Other Components

  • Individual Assignments (20%): 4–6 short tasks (use cases, UML, tests, refactor, small coding).
  • Midterm Exam (20%): Scenario‑based questions on requirements, design, testing, MVP trade‑offs.
  • Participation (10%): Attendance, discussion, code reviews, forum posts.

Team Project — Online Gomoku

Scope

  • MVP: Two players connect, moves sync in real time, win detection.
  • Extensions: Menus (local / invite link / random match), chatbox, graceful disconnects, concurrent games.

Deliverables

  • Repo with clear README, CI, and instructions.
  • Design docs: requirements, UML (class/sequence), architecture diagram.
  • Test suite with coverage of core logic.
  • Deployed demo (TBA platform) for final presentation.

Academic Integrity

All work must reflect your understanding. Cite libraries, tutorials, and AI assistance. Plagiarism or misrepresentation of work will be handled per university policy.
